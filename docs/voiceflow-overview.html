13개 에이전트 구성

상단 Orchestrator가 12개 서브에이전트를 호출. 각 에이전트는 단일 책임(STT, NER, 분석 등)을 맡는다.

01 · 조율

Orchestrator

Stage 순서로 12개 서브에이전트를 호출. 각 Stage 완료 시 상태를 저장하여 실패 지점에서 재개. Self-Heal 루프 진입/탈출도 여기서 제어.

Stage : NONE → STT → NER → DICTIONARY → GROUPING → ANALYSIS → VALIDATION → CLASSIFICATION → NOTION → WIKI
제어 : 상태머신 / 재시도 / 자동 archive(같은 파일 재처리 시 이전 페이지 보관)
02 · 음성→텍스트

STT Agent

mlx-whisper로 한국어 전사. SHA256 캐시로 같은 파일 재처리 비용 차단.

엔진 : mlx-whisper (Apple Silicon)
03 · 고유명사

NER Agent

전사문에서 신규 인명/회사명/업계 약어를 추출. 사전에 이미 등록된 항목은 제외.

모델 : Claude (CLI subprocess)
04 · 사전 교정

Dictionary Agent

custom_terms.txt로 전사 교정 후 신규 항목을 사전에 추가. "원혁명→권용현 부사장" 같은 STT 오인식 보정.

저장 : custom_terms.txt
05 · 세션 분리

Grouping Agent

한 파일에 여러 회의가 섞여 있으면 내용 유사성으로 분리. 같은 주제는 한 페이지, 다른 주제는 별도 페이지.

모델 : Claude
06 · 핵심 분석

Analysis Agent

토픽별 5W1H · 핵심 사실 · 결정사항 · 액션 아이템 추출. 분석 품질이 보고서 품질을 결정.

모델 : Claude Opus
07 · 검증

Validation Agent

분석 결과의 구조와 비즈니스 규칙을 점검. 누락·할루시네이션·길이 폭증을 차단.

판정 : 통과 / 실패 → Self-Heal 진입
08 · 자가 치유

Self-Heal Agent

Validation 실패 시 실패 항목을 분석하여 파라미터를 조정하고 Analysis 재실행을 지시. 최대 5회.

한도 : 5회 → 미해결 시 수동 알림
09 · 분류

Classification Agent

프로젝트 / 회의 유형 / 중요도 / 내부·외부 태깅. 외부 고객 실참 → 외부, 직원끼리 외부 얘기만 → 내부.

모델 : Claude Haiku
10 · Notion 작성

Notion Agent

v3 페이지 양식으로 미팅노트 생성 — 회의개요 표 · 파란 콜아웃 요약 · 빨강 To-Do · 토글 논의 · 노랑 리스크.

API : Notion 2025-09-03 (data_sources)
11 · Wiki 반영

Wiki Agent

생성된 Notion 링크를 세컨드 브레인 Wiki 인덱스에 자동 추가. 토픽 anchor로 후속 검색·브리핑이 가능해짐.

대상 : 000_second_brain/wiki/
12 · 다음날 To-Do

Todo Agent

당일 미팅의 액션 아이템들을 프로젝트별로 묶어 다음날 To-Do로 정리.

출력 : todos_YYYY-MM-DD.json
13 · 일일/주간 브리핑

Briefing Agent

Wiki anchor 기준으로 토픽 그룹핑 → 이성우 담당 To-Do 분리 → Notion 일일 브리핑 페이지 생성. Weekly는 한 주 흐름(시작→진행→결과) 합성.

스케줄 : 평일 07:00 (일일) / 주간 (주말)

Self-Heal 자가 치유 루프

분석 결과가 검증을 통과하지 못하면 사람을 부르지 않고 스스로 재시도한다.

실패 → 진단 → 재실행

Validation Agent가 실패 항목을 구체적으로 지목하면, Self-Heal Agent가 그 실패에 맞게 Analysis 파라미터를 바꿔서 다시 호출한다.

최대 5회까지 시도하고, 그래도 통과 못 하면 사람에게 알린다. 평균적으로는 1~2회 안에 통과.

1
Analysis Agent — 1차 분석 결과 생성
2
Validation Agent — 구조·규칙 실패 항목 지목
3
Self-Heal Agent — 실패 항목 기반 파라미터 재조정
4
Analysis Agent — 재실행 (최대 5회)
5
Validation 통과 → Classification 단계로 진행

출력물

한 번의 실행으로 4가지 산출물이 동시에 생성됨.

Notion 미팅노트

매 미팅 1페이지. v3 양식 고정.

  • 회의 개요 (네이티브 table)
  • 핵심 요약 (파란 콜아웃)
  • To-Do / 담당자 / 기한 (빨강 헤딩 + 체크박스)
  • 주요 논의 (토글 + "쉽게 말하면" 한 줄)
  • 결정사항 · 시사점 · 리스크 (노랑 헤딩)
  • 원문 전사본 (토글)
트리거 · manual_run.sh / hourly orchestrator

일일 브리핑

하루치 미팅을 한 페이지로.

  • Wiki anchor 기준 토픽 그룹핑
  • 이성우 담당 To-Do 분리 섹션
  • 전날 미팅 요약 · 결정 · 액션 정리
  • Notion 일일 브리핑 DB에 자동 저장
스케줄 · 평일 07:00 (launchd)

주간 브리핑

  • 토픽별 시작 → 진행 → 결과 합성
  • 지난 주 추가/수정 Wiki 노트 스캔
  • 지식 격차 · 다음 주 방향 제안
스케줄 · 주간 (Weekly)
